# MACS PR742 candidate export and independent controls

The original #28 MACS bootstrap and PR742 inputs, pinned Repo2RLEnv `27d04ee8203cd5b2f20c3997d13836e5f5b64238`, and the verified #31 native result are frozen. The original validator reported zero F2P/P2P because both stages had collection errors. The opt-in historical rebuild reported one F2P and ten P2P. This protocol tests whether that native recovery can become a Harbor task with positive independent controls.

`export_macs_742.py` calls the pinned upstream `pr_runtime` task builder and Harbor writer with the frozen PR/source/test inputs, the recorded bootstrap actions, the native F2P/P2P lists, and a snapshot of linked public issue #741. The only adaptation is the opt-in `replay_bootstrap_rebuild=true` candidate already tested separately. The deleted original image is replaced with the ownership-labeled reconstructed image whose original 16 actions and smoke/fresh-image checks were verified. This is a candidate export from archived inputs, **not** a fresh run of the official generate CLI. The writer produced ten files with their checksums in `macs-742-export-manifest.json`; private task contents and the public-issue snapshot are kept in `inputs-private/` pending eligibility review.

The only planned execution is the original Harbor 0.6.6 nop/oracle pair at the task's 300-second verifier timeout. The package and test command are unchanged. `run_existing_controls.py`, setup, Docker resource wrapper and cleanup helpers are byte-identical to the #29 controls. The #31 supervisor changes only run/repository identity, target image, evidence paths, and remote time allowance. It uses an existing reserved worker with 4 allocated CPUs, 16 GiB memory and disk, one attempt, 3,600-second job timeout, and no model or GitHub credentials. Harbor verifier containers remain bounded at one CPU and 6 GiB. The two trial wrappers total at most 1,800 seconds; 3,000 seconds are allotted to setup plus trials and cleanup. Up to 4 allocated CPU-hours may be consumed, and prior usage 5.326673 plus that reservation and a 1/6 CPU-hour image-cleanup reservation remain below #31's 16-hour ceiling.

Checkpoint the exact payload and hashes before submission. Record terminal job accounting; download and verify the Iris archive digest, member paths and output hashes; inspect both trial records and reward details. A positive task requires an unchanged ten-file package, complete parseable nop and oracle trials, nop reward zero, oracle reward one, a clean oracle command, and all P2P tests passing in both. Missing or timed-out evidence is inconclusive, not positive. No task/test repairs or retries are authorized by this protocol. After archival readback, remove only the exact labeled reconstructed image on its worker with the ownership-gated cleanup job, verify that image and control-owned resources are absent, and update the issue with result and limits. The issue remains open for user review.
