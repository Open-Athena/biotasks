Title: ancombc2 crashes with 'Quantiles must be in the range [0, 1]' when bias estimation underflows to zero Description: `ancombc2` fails with a NumPy error on datasets where the EM-based bias estimation runs into numeric underflow. A small example that triggers it (4 samples, 3 features, one two-level grouping variable): ```python import pandas as pd from skbio.stats.composition import ancombc2 table = pd.DataFrame( [[154, 188, 68], [143, 63, 177], [30, 154, 96], [131, 167, 150]], index=list('abcd'), columns=['f0', 'f1', 'f2'], ) metadata = pd.DataFrame( {'g': pd.Categorical(['a', 'a', 'b', 'b'])}, index=list('abcd'), ) result = ancombc2(table, metadata, 'g', p_adjust=None).result ``` This raises: ``` ValueError: Quantiles must be in the range [0, 1] ``` The traceback ends in the bias estimation code, at the `np.quantile(beta, (pi1, 1.0 - pi2))` call inside `_estimate_bias_var`. Right before the crash, NumPy also emits the following warning from the EM loop in `_estimate_bias_em`: ``` RuntimeWarning: invalid value encountered in divide resp /= np.sum(resp, axis=0, keepdims=True) ``` From what I can tell, some features end up with such small coefficient variances that all three weighted Gaussian component densities underflow to zero. The responsibility normalization is then zero divided by zero and produces NaN, and the NaNs work their way through the EM updates into the mixture weights, which are later used as quantile probabilities - that is what actually raises the ValueError. Expected behavior: the R implementation of ANCOMBC runs this data without problems, and skbio should too. `ancombc2` should complete and return finite results; for the example above, the `g[T.b]` log fold changes should be roughly -1.083, 0.166 and -0.132, with p-values of roughly 0.258, 0.852 and 0.878. Actual behavior: `ancombc2` crashes with `ValueError: Quantiles must be in the range [0, 1]`, preceded by a `RuntimeWarning: invalid value encountered in divide` during bias estimation.
