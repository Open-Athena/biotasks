# First transport comparison

Pinned original source and license are in `upstream/`; `provenance.json` identifies the main/upstream baseline. `candidate/docker.py` and `transport.patch` change only the script delivery in `DockerSandbox.exec`. The proposed loader reads the complete script from stdin, closes command stdin, then uses Bash's builtin eval rather than passing a script-sized argument through execve. Original `_run`, login-shell mode, working directory, timeout and result capture remain in use.

This is a candidate for review, not an applied live pipeline modification. NUL input is explicitly rejected as before. Shell diagnostic prefixes and `BASH_EXECUTION_STRING` differ, so this is not arbitrary-shell introspection equivalence. The upstream timeout only terminates the local Docker client; remote descendant cancellation is an inherited unresolved boundary and must be tested before calling cleanup reliable.

`python -B check_transport.py` exercises the original and candidate methods through an explicitly labeled local adapter that checks Docker arguments and invokes their actual Bash commands. It tests quoting, UTF-8, newlines, heredocs, stdin EOF, cwd, functions, exit status, stderr, traps, pipefail, errexit, nounset, login mode, actual Linux E2BIG on a large payload, exact payload hashing, builtin-loop timeout and dead-sandbox rejection. It does not exercise a Docker daemon or biological repository. Temporary files are removed by a context manager.

Execution bound: one serial local process, no network/model calls, <100 MiB estimated peak working set and <30 seconds wall time. Use the shared nonblocking heavy-work lock, thread limits, nice/ionice and start/end/exit/peak-RSS evidence. No full repository test suite or new installation is necessary for this isolated standard-library harness.

## Real Docker synthetic probe

`remote_probe.py` compares actual pinned/candidate executors on existing reserved TRC capacity, with no model/repository credentials, no image pulls/builds and no host mounts. It requires cached `python:3.12-slim`, records the resolved image ID/digests, and uses one disposable labeled container at a time (1 CPU,512MiB,64PIDs,network none). Each container auto-removes and has a540second lifetime fallback. Only containers with this probe's exact ownership label can be cleaned up. Shared images are neither created nor deleted.

The job is2allocatedCPUs/2GiB/2GiB disk,600seconds maximum, one attempt, at most1/3allocatedCPUhour, $0model spend and no new capacity. A preflight validates current healthy reserved-worker headroom and payload hashes. Probe results are printed once as structured JSON and saved in the remote working directory. Logs and terminal state must be read back from the original handle; an observation timeout is never grounds for resubmission.

The test covers representative shell behavior, exact large-payload delivery, original errno7 and timeout behavior. After a builtin-loop client timeout, it inspects Bash processes inside only the owned container, then removes that entire container. This diagnoses inherited remote timeout cleanup rather than assuming client timeout kills the command. A missing cached image is an explicit prerequisite failure, not an automatic pull or substitute image. Live biological PR comparisons remain a separate required stage.

## Frozen biological comparison driver

`live-script-manifest.json` binds PR958 (first original Matchms errno7 by batch order) and PR671 (previous successful control) to their acquired base/head diffs. The upstream splitter, targeting and stage builders produce four scripts: PR958 pre/post are 103,780/425,528 bytes; PR671 pre/post are 4,459/6,002 bytes. Original failed script bytes were not retained: this is pinned-ref reconstruction, not byte-identical replay of an old failed invocation. Raw patches/scripts remain private.

`live_validation.py` imports the complete pinned validator, parser dispatcher and all parser dependencies unchanged. Namespace shells avoid unrelated package startup, but no validator/parser functions are replaced. The driver does not run discovery, bootstrap or export and is not a full CLI reproduction. It verifies source and input hashes before execution, uses identical rebuilt image bytes for all four arms, records every executor call, and creates one fresh 1-CPU/6-GiB container per arm. Only `DockerSandbox.exec` differs between original and candidate. Stage commands must match the frozen manifest.

A shared infrastructure guard raises after any executor timeout (exit124), aborting that arm and removing its container before another arm. This deliberately prevents overlapping remote commands, which both original and candidate leave alive after Docker client timeout. It does not change pytest commands, tests, parser rules, rebuild behavior, command timeout (600seconds), or upstream outcomes for completed invocations. A timed-out arm is censored rather than interpreted as a PR result. No restart or task repair is automatic.

Before submission, a bounded supervisor must reconstruct the saved Matchms recipe with only an ownership label, pass its verified image ID, archive raw evidence privately, and remove all owned images/containers/cache. The image is a reconstruction with possible dependency drift, not the deleted original.
