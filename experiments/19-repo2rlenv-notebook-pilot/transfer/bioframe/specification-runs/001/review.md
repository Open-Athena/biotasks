## Selected target

The notebook's terminal scientific product (`inputs/plan.json`, `inputs/exports.py`) is `df_peaks_maxmotif_clean`: CTCF ChIP-seq peaks (HFF, ENCODE ENCFF401MQL, GRCh38), each assigned its strongest overlapping JASPAR MA0139.1 CTCF motif, then trimmed for proximity (±1 kb) to ENCODE blacklist regions (ENCFF356LFX). The whole 9-column table is exported with no recomputation, so the public task is the full pipeline from the three supplied source files; no derived intermediate is needed (the pipeline is a stable, deterministic set-operation analysis, ~5 s and ~550 MiB in the trial run per `trial/result.json`, well within the 4-CPU/8-GiB sandbox).

- Public schema renames the reference columns (`chrom,start,end,fc,chrom_2,start_2,end_2,pval_2,strand_2`) to meaningful names; grader maps by position (handoff). Row order is free: the reference's row order follows the peaks-file row order because `subtract` re-sorts by df1 index labels (bioframe `ops.py:477,549-550`) and `df_peaks_maxmotif` carries non-monotonic labels from `.loc[idxmax...]`; `output-audit.json`'s preview (chr19, chr4, chr1 rows, ascending fc) confirms the output is not chromosome-sorted. Order is representation, not content.

## Fidelity of the executed reference (bioframe 0.8.0 source verified)

- `read_table` with `narrowPeak` / `jaspar` schemas (`bioframe/io/fileops.py:63-75`; `bioframe/io/schemas.py:77-88,120`); JASPAR track has one leading track-declaration line (reference used `skiprows=1` and parsed cleanly).
- `overlap(peaks, motifs, how='left', return_index=True, suffixes=('_1','_2'))`: half-open intervals, overlap requires sharing ≥1 base (`bioframe/core/arrops.py:338-354`, `closed=False` default); exact chromosome-string grouping (`ops.py:287-303`); unpaired left rows get null right-side fields (`ops.py:510-539`); output sorted by (peak file row, motif file row) (`ops.py:549-550`). Therefore `groupby(['chrom_1','start_1','end_1'])['pval_2'].idxmax()` after `fillna(-1)` selects, per distinct peak interval, the max-`pval` motif, ties resolved to the earliest motif row in the supplied track; peaks with no overlapping motif are retained as rows with blank motif fields. This tie-break is not incidental: it determines which motif row is reported, so it is stated in the public question in source-identifiable terms (file row order).
- `expand(blacklist, 1000)` pads both sides by 1000 bp (`ops.py:208-212`); `subtract` removes peak portions covered by the expanded blacklist via complement overlap, splits peaks into surviving sub-intervals carrying fc/motif columns, and drops fully covered peaks (`ops.py:1314-1329`). Assignment precedes filtering, per the tutorial; my public spec fixes that ordering.
- `output-audit.json`: 40,557 rows; expected column set order; blank `chrom_2` count == blank `pval_2` count (5,765), consistent with no surviving row having motif coordinates but missing pval (edge semantics still verified in validation).
- Reference-environment caution: the reference program relies on pandas 2.x chained-assignment `replace(-1, nan)` (worked under pandas 2.3.3 with a logged FutureWarning, `trial/result.json`); under pandas 3.x it would silently no-op. The reference environment stays pinned; solvers are unconstrained (software choice open, bioframe offered for convenience only).
