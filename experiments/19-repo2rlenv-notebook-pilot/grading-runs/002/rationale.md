**Evidence base.** Three executed artifacts were available for calibration: the projected reference `cluster_marker_genes.csv` (398,259 rows = 17 clusters × 23,427 genes), the oracle recomputation, and a fully independent second implementation (numpy/scipy/h5py only, no scanpy). I additionally ran a scanpy `rank_genes_groups(method="wilcoxon")` control on a spec-faithful normalized matrix built from the declared inputs (pooled intersection universe, ≥100 detected genes reproducing `cell_groups.csv` exactly, ≥3-cell gene filter giving 23,427 genes, pooled median total 5853.0, log1p). This established the dominant numerical fact: the reference was computed on **float32** normalized values (scanpy's pipeline stores `normalize_total`/`log1p` output as float32), which changes rank ties relative to a float64 evaluation and shifts `W` by rank units. Measured agreement with the reference: score max |Δ| = 1.05e-4 (oracle), 1.01e-4 (independent), the two float64 implementations agreeing with each other to 6.7e-5; a scanpy run on a float32 pipeline matches the reference to 3.7e-6, confirming the source of the residual. log2fc agrees to 1.93e-6 (float32 storage of `logfoldchanges`); p-values to ≤2.3e-3 relative, exactly the |z|·dz propagation expected from z-noise of 1e-4 at |z| up to 86.

**Tolerances.** score atol 2e-4 (≈2× the worst measured discrepancy; a 1.5e-4 shift passes, 2.5e-4 fails — boundary tested); log2fc atol 1e-4 (50× the observed 1.9e-6 float32 noise; a 1e-3 shift fails); p rtol 1e-2 (5× the worst measured 2.3e-3; 5% shifts fail). These are all derived from the recorded float32/tie-residual evidence, not copied from a universal epsilon, and each field keeps its own scale (no relative tolerance on score, whose meaningful scale is absolute rank-units; no absolute tolerance on p, whose scale is its own magnitude).

**The p-value underflow zone** was calibrated against measured behavior: the reference reports 0 for |z| ≥ 37.70 (double `2·sf` underflow), while a float64 evaluation can retain values down to ~1e-311 there (the independent implementation reports 65 such rows, all ≤ 4.4e-311, and one BH-scaled `pval_adj` of 5.8e-308 where the reference reports 0). Conversely the reference's smallest *nonzero* values (p = 1.25e-310, padj = 2.2e-308, and normal doubles up to 1.6e-303 at |z| ≈ 37.2) must not be collapsible to 0, because a faithful evaluation cannot underflow at that z. The zone 1e-303 sits above the reference minimum nonzero padj (2.2e-308, BH-scaled from a subnormal p by up to m/j) and below the reference's regular 1e-290 values; a perturbation that zeroes subnormal-but-resolvable tails (p in (1e-303, 1e-300]) is correctly rejected, while the legitimate 0↔5.8e-308 straddle is accepted.

**Structural checks** derive everything dynamically from the reference (labels, gene universe, per-cluster counts G); no expected dimensions or answer values are embedded. Alignment is by (cluster, gene) string identity, not row position. Rank ordering is checked as a tolerance-banded descending-score condition rather than requiring an exact permutation, because the reference's own scores contain thousands of exact ties and near-ties per cluster: measured rank displacement between the reference and a faithful recomputation reached 143 positions inside a dense tie band, while the banded condition is satisfied (max upward step 5.3e-5 ≪ 2e-4). An exact-rank check would fail correct scientific outputs. A crafted tie-reordering submission passes, as intended.

**Controls exercised:** both recomputations and a self-comparison pass; missing file, empty table, wrong/permuted header, blank field, NaN, non-integer rank, dropped/duplicated rows, renamed gene, relabeled cluster, shuffled rows, rank swap, per-field perturbations just above tolerance, 3-digit score truncation, tie-corrected variance, constant p-values, and omitted BH all fail with the intended check. The 6 significant-digit output rule is intentionally not enforced as a digit-count test (the reference itself prints `1.0` for adjusted p-values of exactly 1); precision degradation is caught by the numeric comparisons instead, as documented in the public instruction.

**Limitations.** (1) Portability across arbitrary software stacks is not claimed beyond the demonstrated agreement of two independent implementations plus a scanpy control; byte-identical reruns of the reference run were not used as evidence. (2) The score tolerance is calibrated to the observed float32-vs-float64 tie discrepancy; a submission that went out of its way to replicate scanpy's exact internal order would pass trivially, and one that introduced an error below 2e-4 in z would pass undetected — quantities at that scale are not resolvable by this dataset's evidence. (3) The grader never reads the task inputs; the population/gene-universe reproduction is enforced implicitly through key coverage against the reference's cross product rather than by re-deriving the filters, which keeps the grader fast (≈11 s) and avoids duplicating the scientific method. (4) The `rank_consistency` check's banded form accepts any deterministic tie break, which is the documented freedom; it is not an equivalence I could validate beyond the two recomputations plus the crafted tie-reorder control.
