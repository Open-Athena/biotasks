## Evidence base

I inspected the three private reference files in `/work/reference` (read-only), the pinned scanpy 1.12.4 / anndata 0.13.4 / pandas 3.0.6 / numba sources in `/work/venv`, and the source notebook/export code supplied in the specification. No rerun of the analysis was performed; no reference value, dimension, cluster count or hash is embedded in the grader. Measured observations below are used only to *justify comparison rules*, never to relax them.

## Key scientific/serialization facts that drove the design

1. **Storage precision is heterogeneous and I verified it from the reference files themselves.** Every text token in `scores` and `logfoldchanges` of file B and in `umap_1`/`umap_2` of file A is exactly `str(np.float32(value))` (checked over all 398,259 DE rows × 2 columns and all 34,082 UMAP values — zero exceptions). This matches `scanpy/tools/_rank_genes_groups.py:889-896`, which stores `scores` and `logfoldchanges` with `dtype float32` while `pvals`/`pvals_adj` use `float64`, and `scanpy/tools/_umap.py:255` (`np.ascontiguousarray(x, dtype=np.float32)`). This is the *serialization/precision argument* the policy asks for: the exported digits carry exactly binary32 information for scores/logfoldchanges/UMAP and full binary64 information for p-values. Hence: binary32-rounding equality for the former three; exact double equality for the p-values. This is not a copied "universal epsilon": it is derived per column type from the reference's own storage.
2. **p-values are bit-reproducible.** Recomputing Benjamini–Hochberg from the stored `pvals` with statsmodels reproduces `pvals_adj` bit-exactly — but only when the CSV is parsed with a round-trip-exact parser. pandas' *default* float parser introduces 1-ulp errors on ~158k p-value rows (measured), which would silently break exact comparison. The grader therefore uses Python's own `float()` (correctly rounded, round-trip exact) rather than pandas. This justifies the exact-equality rule for `pvals`/`pvals_adj`: the values are deterministic functions of the stored doubles, and float(text) recovers them exactly.
3. **Ties are the only legitimate ordering ambiguity.** The reference DE table contains enormous exact-tie runs (134,665 adjacent row pairs with byte-identical `scores`, `pvals` and `pvals_adj`; several runs exceed 400 rows). Within such a class the leaderboard statistics are identical, so only gene identity and the per-gene `logfoldchanges` differ. The public contract therefore permits permutation of rows *strictly inside* a class of rows with identical (score, pvals, pvals_adj), and nothing else. I verified from the reference that tie classes are contiguous and that equal scores imply equal p-values within a group, so the rule is well-defined and validated on the actual data. Any cross-class move is caught by `de_gene_ranking`/`de_logfoldchanges`.
4. **No label or orientation equivalence is offered**, per the policy's requirement to resolve consequences before allowing a variation. The literal map in step 11, the DE `group` column, the cross-file label identity and the stored group order all depend on exact label strings; a relabeling cannot be validated without re-deriving every dependent endpoint. UMAP sign/rotation invariance is likewise not validated. Mutation tests confirm consistent relabeling in both files still fails, as intended.
5. **Row-count / block structure is compared, not trusted.** The reference's group blocks are consecutive, one per group, each with an identical number of rows (17 × 23,427) and an identical gene universe per group; the grader compares all of these dynamically against whatever the submission contains, without embedding counts.

## What the grader does (and why)

- Pure-stdlib (csv/json/struct/re/math/os/argparse), no numpy/pandas: avoids parser-level 1-ulp noise entirely and keeps the verifier at ~9 s wall / ~715 MiB RSS against the 120 s budget and 8 GiB sandbox. Deterministic: repeated runs produce byte-identical reports (verified).
- Reads reference values dynamically; every expected value, count, label set and ordering comes from the reference files at run time.
- Every declared check is emitted exactly once per run, including for empty, missing, malformed, non-UTF-8, oversized and byte-mutated submissions (33 distinct failure families exercised).
- Bounded reads: row limit (2× reference rows + 1000) and byte limit (4× reference bytes, minimum 64 MiB) derived from the reference keep adversarially large submissions from unbounded work; those cases still fail checks, exit 0 and yield valid reports.
- Nonfinite/invalid handling: `nan`, `inf`, `Infinity`, empty fields, `1_0`, BOM, invalid UTF-8, NUL bytes and out-of-range p-values are explicit failures. Exact zeros are preserved and compared (zero vs nonzero mismatch is a distinct failure).
- Cross-file: DE `group` set must equal file A's `leiden_res_0.50` label set; the two files' row units are kept distinct in both the code and the messages.
- Lives exactly at the public contract's stated rules; no hidden tolerance, no hidden leniency.

## Validation performed

- Reference vs itself: passes all 16 checks (repeatability basis).
- Missing each of the three files individually, all-missing, empty, header-only, and file-replaced-by-directory: correct targeted failures.
- 78 mutation families (from permuted rows, dropped/duplicated rows, header changes, extra columns, BLANK/nan/inf/1e999/NUL/BOM/CRLF/quoting/no-trailing-newline variants, relabeling, tie-class permutations, cross-group score/p-value/label swaps, per-group gene-set changes, parameter key/value/type/dup-key/NaN-constant changes, oversized files): every family fails at least one named check with an accurate message; every intended-to-pass representation variant (CRLF, quoting, extra digits/^ scientific notation with the same value, tie-run permutation, JSON key order/whitespace, unlisted extra files, directory-name independence) passes. Only pure serialization changes are accepted; all value or identity changes are rejected.
- Boundary tests of the binary32 rule: values exactly at the f32 rounding midpoint are accepted (round-to-nearest-even) and values 1e-12 beyond the midpoint are rejected; ±1 f32 ULP mutations fail.
- Determinism, no-writes to reference/submission, path-independence, JSON report schema exactness (`{"passed", "checks":[{id, passed, message}]}`), exit 0 for both passing and failing submissions, nested report directory creation.

## Limits and remaining assumptions (not blockers)

- **Tie-permutation leniency is bounded by evidence.** I could not mathematically prove that no pair of distinct reference rows shares a tie class across different gene identities in a way a solver could exploit; I verified empirically that the reference's tie classes are contiguous and that equal scores imply equal p-values, so the rule is exactly as permissive as the reference permits and no more. The `de_gene_ranking` check still compares gene identities inside every class, so it cannot be satisfied by an arbitrary permutation.
- **Reference-only evidence.** The floating-point rules (exact-double for p-values, half-ULP binary32 for scores/UMAP) are justified by the pinned stack's measured storage precision and the pinned-stack user's bit-identical repeatability record, not by a cross-implementation study; the first non-pinned-stack solver may reveal a genuinely different UMAP realization, which would then fail the strictly stated coordinate rule. The byte-identical repeated-run evidence is not treated as proof of cross-stack portability, and no such equivalence is claimed in the public contract.
- **No claim of equivalence for scientific variants.** The tie-class rule is the single permitted ordering variation, and it is fully resolved against every dependent endpoint (it affects only `DE file` row order, not the group set, per-group universe, per-(group,gene) statistics or the file-A endpoints). No other transformation (label remap, coordinate transform, sign flip) is offered.
