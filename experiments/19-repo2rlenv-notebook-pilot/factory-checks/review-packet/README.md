# Lossless file-backed review input — offline candidate

A final review in the fixed panel was rejected on its first provider request because its initial context was too large. It contained generated programs, full controls, diagnostic outputs and catalogs; there was no accumulated review conversation to discard. Retrying unchanged input cannot resolve that boundary.

The next-version reviewer now receives the task, policy, interface and control summary together with an index of the complete original input. Every field is saved in an immutable, versioned, hash/size-bound JSON document. The reviewer uses `read_review_evidence` to select a field and optional RFC6901 pointer, inspect object keys/array length, or read exact strings and formatted records in explicit windows. No source, check, probe, hint or diagnostic value is removed or summarized. Object member order, arrays, Unicode and code strings are preserved. Packet snapshots share the existing deadline and grant no execution, shell, filesystem write or arbitrary-path access.

The controller verifies the document and manifest identities before returning any selected content. Modified/missing/linked evidence remains a gap, and expired reads do not extend the deadline. A changed input receives a distinct packet; earlier packets remain intact. Only review and repair-review stages receive this tool. Existing package, reference and execution evidence tools remain available. The independent implementation and probe authors receive no new private evidence. Acceptance still uses the original complete controller state and unchanged source/fixture/scientific/control refusal callback.

[An offline replay](replay-189.json) reconstructs every value from the preserved failed input: 752,138 bytes of original JSON values become 17,226 bytes of initial model-context JSON, with all fields available through the packet. The captured input file itself is 881,234 bytes including formatting. These are context-size measurements, not token estimates or a claim that a provider accepted a new request. The admission callback's AST is unchanged. No model, science, grader or original artifact was rerun/edited.

[308 affected checks and 234 project tests pass](offline-checks.json), including full review/repair orchestration through the actual read-only handler, controller-owned failed-control refusal, exact reconstruction/member order, selective source/code reads, malformed pointers, changed/linked documents/manifests, deadline refusal and existing private-asset/native-packaging boundaries. Ruff, formatting, ty and pre-commit pass. The initial two stale fake-review tests and immutable-manifest refusal remain recorded; no original failure was replaced with a passing claim.

This candidate is not in the frozen 224-file development panel. It introduces no arbitrary byte/token limit, scientific simplification, new worker stage or repair/resource allowance. Read windows are explicit selections with full extent metadata, not silent truncation. Existing context-history recovery can still discard accumulated exploration when the provider rejects that history, while the complete packet remains inspectable.
