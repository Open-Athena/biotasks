# Distinguish endpoint eligibility from export availability

The canonical next-version prompts now distinguish a scientific non-target from an independently interpreted result that is inaccessible to append-only export. Both remain entries in the existing `excluded_outputs` strings; no new response fields or inventory are introduced. An unavailable endpoint needs an original source location, necessary state and an unresolved recovery handoff. Preparation still cannot capture earlier values or recompute science.

The specification writer and its independent reviewer now apply the already-existing final source-audit rule earlier. Subsumption needs the same scientific operation, entities, input state, consequential parameters and meaningful result fields, with a real projection to the retained counterpart. Shared inputs or a larger output are insufficient. Supplying an upstream dependency does not permit giving away or removing another independent scientific answer.

[Evidence](evidence.json) compares two archived domains:196 was rejected for omitted coverage and unsupported subsumption, while accepted 198 faithfully recovered a result whose variable was overwritten. This is operator inspection of actual original evidence, not a new scientific execution or a claim that the new prompts will produce correct proposals.

The static wording review preserves these distinctions:

| Situation | Required handling |
| --- | --- |
| A meaningful result is overwritten or unnamed | Record its source and recovery gap; apply the existing faithful-recomputation policy later. Do not silently omit it. |
| A larger result contains the same scientific result as a true projection | Identify the retained counterpart and projection; avoid a redundant target. |
| Different operations use the same data | Shared input does not establish subsumption. Check each scientific role. |
| A statistic or plot is solely supporting diagnostics | Keep source-backed exclusion available; do not turn every operation into an endpoint. |
| A result exists only inside plotting internals | Preserve the existing restriction on custom reconstruction; this change grants no recovery permission. |
| No result can be exported within preparation’s contract | Retain the existing rejection route and report the limitation precisely. Do not label the source scientifically broken. |

No hand-edited notebook, answer, endpoint inventory or generated task is supplied to workers. [Next-version identity and offline checks](../../panel-rounds/104/offline-checks.json) record the actual prompt files. Running103 campaigns retain their original prompts. Fresh source-only execution and independent coverage/native/release gates are still required before any qualification claim.
