# Earlier discovery of installed answer assets — candidate, not adopted

The fixed 224-file panel is unchanged. This note identifies reusable code for a
possible later version; it does not qualify a task or change repair allowances.

## What the retained failure establishes

In [185](../../panel-rounds/089/rejection-185.md), the construction worker assessed
the final installed catalog, but a later grading repair identified a partial
expected answer in installed regression-test source. That repair role could not
change the environment. The construction prompt already explicitly covers
partial answers in code and text; another warning alone would not address the
difference in available evidence or editable scope.

The current final-environment operation supplies file identities and discovery
candidates. Numeric literal-to-output hints are generated later by
`ReviewInspection.prepare_asset_value_hints`. That helper uses the final
materialized outputs, including recovered endpoints, and checks package-source
bytes against the installed-file hashes before considering their contents.

## Smallest candidate to assess after the fixed round

Reuse the lexical and streaming table inspection in `asset_value_hints.py` during
the existing construction operation, after final derivation/oracle execution.
Give the same worker advisory matches while it can still declare unused-file
exclusions through `environment_review`. Use the actual installed files and
recorded distribution ownership; a release archive is usable only when its bytes
match those installed identities.

Keep the current ownership boundaries: GLM decides whether a match represents a
requested answer and whether its file is unused. The controller applies only
exact, hash-bound declarations and reruns derivation/oracle after a change.
Bind subsequent inspection to the new output/catalog identities. Independent
grading and review remain required.

These hints contain answer values. Keep them in the author-readable, root-owned
inspection area that the isolated oracle cannot access; exclude them from the
solver image and learner inputs. Charge inspection to existing construction and
campaign deadlines, with explicit coverage when inspection is unavailable.

The existing discovery radius is not a grading tolerance. Magnitude matches can
be unrelated, and current coverage excludes integers, comments, strings,
non-Python sources, nonpriority files and non-CSV/TSV outputs. Neither a match nor
an absence authorizes deletion or certifies isolation. Preserve those limits
rather than turning the heuristic into a new acceptance gate.

## Alternatives and evidence needed

Pinned Repo2RLEnv `5555443` already repairs packaging as well as instructions and
verifiers, and its repair prompt asks for grounded defects to be addressed
together. Its generic loop defaults to three rounds; that default is not this
pilot's single shared allowance. Replacing the scientific pipeline with that
loop would also need preservation checks for methods, inputs and endpoints.

Broader repair ownership could address late environment findings, but would
require rebuilding the environment and revalidating all affected scientific and
native evidence. Earlier advisory evidence is a smaller candidate that uses an
existing owning stage. Neither guarantees that GLM will classify a match correctly.

Before adoption, test new and recovered outputs, installed/source hash mismatch,
unrelated near matches, required files and notices, changed exclusions, stale
inspection after failed execution, deadline exhaustion and oracle/solver
isolation. Assess outcomes across domains before selecting a new runtime; do not
add a notebook name, package-specific deletion or expected scalar to a prompt.
