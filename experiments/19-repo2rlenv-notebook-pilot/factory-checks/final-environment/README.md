# Review installed answers against final executed endpoints

Construction now executes a candidate before asking its existing GLM worker to review installed assets against the final input/reference/oracle inventory, including recovered branches. The controller returns exact artifact and catalog identities. GLM inspects actual candidate files, assesses answer exposure and unused status, and may declare additional distribution-relative files by content hash and reason. It cannot change the frozen base removals or restore a file during the session. Filename/number matches alone never select a removal or supply a reward.

Only the controller applies declarations, using the task virtual environment. A changed environment requires fresh derivation and isolated oracle execution, then a review bound to the new inventory/catalog. An unchanged assessment reuses the actual completed computation. Original reference evidence remains unchanged. The effective combined removal manifest reaches the fresh grading environment, independent review hints and native image; private reasons/catalog stay outside the solver image. Later scientific controls, independent review and native qualification remain required.

This uses the existing construction worker and campaign/resource/time allowances. It adds no separate stage, global quality repair, reference-setup test, model/token allowance or seed-specific path. The original frozen177–184 runs are unchanged. [182 offline checks](offline-checks.json) include a real isolated-venv CLI check and synthetic construction/packaging boundaries. They do not establish model adherence or biological correctness.
