# Verified local archive caches

`readback_cache.py` bounds local storage during an independent original-archive download. A duplicate remote object is still streamed and verified before sharing a local regular-file inode. Only equal SHA256, byte count and permissions may share storage. Original manifests, download receipts, remote objects and every local path remain intact. Treat these caches as immutable evidence, never as working directories.

`consolidate_cache.py` extends the same representation across already independently verified completed archives. It checks every distinct original inode against its sealed identity before replacing any name, creates a temporary hardlink, atomically replaces only the identical copy, then verifies the resulting group. A durable private journal records each attempted/completed link; a failed replacement retains the original file and removes only its own temporary. Unknown metadata, symlinks and changed bytes/permissions are refused.

No biological payload, source program, permission, original readback receipt or remote object changed. Small files were not consolidation candidates. `consolidate_publication_views.py` also admits immutable evidence copies belonging to completed publications, only when their original export manifest exactly matches an independently verified archive. It reuses the same content/mode verification and atomic linking helper; it preserves task paths, files, manifest bytes and receipts. Unpublished working directories, unknown seals, missing originals and symlinks are refused. Seventeen cache tests pass, including six new selection/refusal cases. This is operator storage maintenance; no runtime, scientific task or execution budget changes. [Checks](publication-cache-offline-checks-20261027.json), [dry run](publication-cache-dry-run-20261027.json).
