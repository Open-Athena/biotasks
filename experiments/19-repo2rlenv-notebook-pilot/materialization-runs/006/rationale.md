**Diagnosis and correction of the second rejection (a storage-reader defect; the scientific target is unchanged).** Two interface corrections were confirmed by the run: the derive completed with both stage inventories accepted, and the isolated oracle reached its first matrix read. The remaining failure was the oracle's own pre-construction validation, which demanded `len(indptr) == n_features + 1`. In the 10x filtered-matrix layout, `matrix/shape` is `[n_features, n_cells]` and the compressed-sparse axis is the **cell** (barcode) axis — `indptr` spans cells while `indices` hold feature rows — so the files are well-formed and the check was wrong. The reader now identifies the cell axis from the file itself (the barcode list), accepts that `indptr` spans either stored dimension (with the feature-major interpretation as a warning fallback), reconciles entry-array/pointer length disagreements defensively, rounds non-integer counts, and warns on negative values rather than aborting; only genuinely unrecoverable ambiguity remains fatal. This removes an incorrect assumption without changing any computation on the data, since the matrices are marked up exactly as before once constructed. The same revision replaced the two dense copies per rank chunk with a cells×genes chunk (`rankdata(axis=0)`) and a single sparse-indicator product for the per-cluster normalized-value sums, trimming resident memory and runtime.

**Restructuring of the prior worker draft (scope unchanged).** The prior worker attempted byte-level mimicry of scanpy's internal float32 arithmetic (sequential float32 per-cell accumulation, float32 size factors), recomputed the full cell ranking once per cluster (17×), and used per-entry Python loops for ranking. Nothing scientific was lost by replacing it: sequential float32 summation of small integer counts is mathematically identical to exact integer summation (every partial sum is an integer below 2^24); scanpy's exact internal operation order is not part of the public definition; and the 17× re-ranking and per-entry loops were genuine timeout risks. Float32 storage noise in the recorded reference is instead handled where it belongs — in acceptance tolerances.

**Unresolved validation questions (calibration, not scope).** (1) The recorded reference statistics were stored as float32 (its CSV values carry 7–8 significant digits), so comparisons need tolerances above float32 representation noise (~1e-7 relative) regardless of implementation. (2) A reference computed on scanpy's float32 normalized values can tie or order cells differently from a spec-faithful float64 evaluation where scaled counts coincide; rank sums are unchanged under re-ordering within a tie group, but mixed in-group/rest near-ties can shift W by ~0.5 each, so score noise ~1e-4 absolute and adjacent-rank swaps for scores within ~1e-3 are expected — rank mismatches among score-equal-within-tolerance genes must count as numerical, not methodological. (3) The stable `erfc` tail is mandated; if the recorded run used a less stable `2·(1−Φ)` route, percent-level relative differences are possible only for p ≲ 1e-14 (absolute ≲1e-16); underflow-to-zero must compare equal, and if its BH ran on float32-truncated p-values that noise propagates into `pval_adj`. (4) `log2fc` is amplified by the 1e-9 stabilizers in the near-zero-mean regime, where the means are exact, so expected agreement is ~1e-6 — the tightest field to calibrate. (5) Exact, non-tolerance checks: (cluster, gene) key sets and per-cluster row counts (17 × 23,427 = 398,259 rows expected from the recorded artifacts), the integer tested-gene universe, cell-population reproduction and label equality. (6) The interface question that caused both rejections is now resolved for both stages (declared paths relative to the stage directories; a single output written directly under `--output-dir`); the remaining residual risk is a runtime one, not a layout one.

**Exploratory vs controlled.** The earlier campaign's reference observations (file integrity, cell/cluster/gene counts, score ranges, float32 digit counts) were structure and integrity inspections of the recorded artifacts, not an independent scientific reproduction, and none are embedded as expected answers. The controlled steps are: derivation under md5 verification with structural consistency reporting (whose diagnostic output is now recorded evidence), isolated oracle execution from the four declared inputs only, and the numerical comparison against the projected reference performed by the validation workers. A successful isolated execution hands off to that comparison and is not by itself proof of scientific validity.
