# Task: preprocessing, clustering and marker-gene analysis of two bone-marrow scRNA-seq samples

## 1. Scientific objective

Reproduce, from raw 10x count matrices, the complete "Preprocessing and clustering" single-cell RNA-seq workflow: QC-motivated filtering, per-sample doublet detection, normalization, feature selection, dimensionality reduction, neighborhood-graph construction, UMAP embedding, Leiden clustering at four settings, manual broad-lineage annotation, and per-cluster differential-expression (DE) marker-gene ranking (Wilcoxon, each cluster vs the rest). Deliver three output files: a per-cell table of cluster assignments, annotation, sample identity and UMAP coordinates; a per-cluster DE ranking table; and the DE run parameters.

Biological context: bone-marrow mononuclear cells from two healthy human donors (NeurIPS 2021 openproblems benchmark; 10x Multiome, Gene Expression library used here). The analysis is per-cell and unsupervised, batch-aware where indicated, and runs on the union of both samples with no batch correction or integration. The donor samples are treated as batches for QC-motivated steps only.

## 2. Inputs (task-relative paths; the packaging layer assigns their actual locations)

- `inputs/s1d1_filtered_feature_bc_matrix.h5` — 10x filtered feature-barcode matrix, sample `s1d1`. md5 `a99285913ea3f3d22600d3d2f8a88e34`.
- `inputs/s1d3_filtered_feature_bc_matrix.h5` — 10x filtered feature-barcode matrix, sample `s1d3`. md5 `825f7f7578e3dc0b8955f5a97a402338`.

Each is a 10x HDF5 (matrix/features layout) holding barcodes and features; the feature set includes both Gene Expression and Chromatin Accessibility features. Only features of type "Gene Expression" are used. Cell (barcode) order and feature order are the file orders. Expect on the order of a few thousand cells per sample and roughly 36,000 measured genes.

## 3. Analysis procedure — execute in this exact order

General rules: use the parameters given (defaults listed are the required ones); every stochastic element is seeded with 0 as indicated; no cells or genes are removed other than by the specified filters; no downsampling, subsetting, batch correction or integration; results are computed on the full data. Reference anchors (scanpy operations) are given for semantic precision only — any stack implementing the same operations with the same parameters is acceptable, and the behavior of the named reference versions must be reproduced.

**Step 1 — Load each sample.** Read the 10x HDF5 and keep only features of type "Gene Expression". Rows = the file's barcodes in file order; columns = feature names in file order, with `gene_ids` and `feature_types` kept as per-gene metadata. Make gene names unique by suffixing "-1", "-2", ... to the second and later occurrences of each duplicated name (the first occurrence is unchanged). Anchor: `scanpy.read_10x_h5(path)` then `.var_names_make_unique()`; anchors resolve against scanpy 1.12.4.

**Step 2 — Concatenate.** Concatenate the two objects along cells, `s1d1` first, then `s1d3`, using the intersection of gene names (inner join, gene order as in the first object); keep each sample's cell order unchanged and do not rename cells during concatenation; add a per-cell categorical column `sample` with values `s1d1` / `s1d3`. Then make cell names unique with the same suffix rule applied in row order: a barcode that occurs again later receives "-1" (s1d1 cells therefore keep unsuffixed barcodes; a s1d3 barcode that also occurs in s1d1 becomes `<barcode>-1`). Anchor: `anndata.concat(adatas, label="sample")` then `.obs_names_make_unique()`.

**Step 3 — Gene flags.** `mt` = name starts with "MT-"; `ribo` = starts with "RPS" or "RPL"; `hb` = name contains the regular expression `^HB[^(P)]`.

**Step 4 — QC metrics (diagnostic).** Per cell: total counts, number of genes with counts above zero, natural log1p of both, and the percentage of the cell's total counts falling in mt / ribo / hb genes plus log1p thereof. Per gene: total counts, number of cells with counts above zero, log1p of both. Not exported; feeds only the visualizations.

**Step 5 — Filtering.** Keep cells with at least 100 genes having counts above zero (recompute this count from the count matrix, not from step 4). Then keep genes expressed (count above zero) in at least 3 cells. Apply both to the whole two-sample object, not per sample.

**Step 6 — Doublet detection (Scrublet, per sample; diagnostic).** Within each `sample` separately on the filtered raw counts: simulate doublets at 2x the number of observed cells (each simulated doublet adds the counts of two randomly drawn observed transcriptomes, no UMI subsampling); inside the routine gene-filter to >= 3 cells and cell-filter to >= 3 genes; median-count normalize; log1p; select highly variable genes within the sample (Seurat dispersion flavor, 20 mean-expression bins, cutoffs mean in [0.0125, 3] and normalized dispersion >= 0.5); simulate doublets from the raw counts; normalize observed and simulated to a common 1e6 total; embed both with PCA (30 components, mean-centered, variance-normalized, arpack-equivalent, seed 0); classify with euclidean kNN using round(0.5 * sqrt(sample cell count)) neighbors; expected doublet rate 0.05 (stdev 0.02); doublet threshold chosen automatically from the minimum between the modes of the simulated-score histogram; seed 0. Record per-cell `doublet_score` and boolean `predicted_doublet` on the full object. This step must not alter expression values or the cell/gene sets; its outputs are diagnostics and are not exported. Anchor: `scanpy.pp.scrublet(adata, batch_key="sample")`.

**Step 7 — Keep a copy of the filtered count matrix** (e.g. a `counts` layer). Diagnostic; not exported.

**Step 8 — Normalization.** Compute each cell's total count; the dataset-wide target is the median of these totals; scale each cell so its total equals that median; then apply natural log1p. Anchor: `sc.pp.normalize_total(adata)` followed by `sc.pp.log1p(adata)` (the log base is natural; the DE fold-change step inverts it with expm1).

**Step 9 — Feature selection (HVG).** Select 2000 highly variable genes, Seurat dispersion flavor, selected per sample and merged across samples: within each sample separately (genes unexpressed in that sample excluded), bin genes into 20 mean-expression bins, estimate dispersions, normalize dispersions per bin (a bin with a single gene gets normalized dispersion 1), and mark genes passing the Seurat cutoffs (mean in [0.0125, 3], normalized dispersion >= 0.5) as HVG in that sample; then rank genes across samples by the number of samples in which the gene is HVG (descending), breaking ties by the mean over samples of the normalized dispersion (descending), and take the top 2000 as a boolean `highly_variable` flag in the original gene order (also record per-gene mean/dispersion annotations and the per-sample HVG counts). All genes remain in the object; do not subset. Anchor: `sc.pp.highly_variable_genes(adata, n_top_genes=2000, batch_key="sample")`.

**Step 10 — PCA.** Compute PCA (SVD of the column-centered matrix) on the 2000 highly-variable genes of the log-normalized matrix, 50 components, seed 0; store the 50-dimensional per-cell representation `X_pca`. Anchors: `sc.tl.pca(adata)` (selects the `highly_variable` mask by default, computes 50 components, zero-centered arpack on the sparse log-normalized matrix, `random_state=0`).

**Step 11 — Neighborhood graph.** From `X_pca` (all 50 components), find each cell's 15 nearest neighbors under euclidean distance and compute symmetrized connection weights with the UMAP fuzzy-simplicial-set construction (local connectivity 1, sigma/rho normalization, fuzzy-union symmetrization, as in umap-learn's default `fuzzy_simplicial_set`). Seed 0. The reference stack uses an approximate kNN index (pynndescent) at this dataset size; an exact 15-nearest-neighbor implementation of the same specification is an acceptable equivalent. Anchor: `sc.pp.neighbors(adata)` (n_neighbors=15, metric euclidean, method "umap").

**Step 12 — UMAP.** Compute a 2-dimensional UMAP embedding of the connectivity graph with min_dist 0.5, spread 1.0, spectral initialization, negative sample rate 5, initial learning rate 1.0, repulsion strength 1.0, and 200 epochs (the dataset has more than 10,000 cells), seed 0; the a/b curve parameters are those umap derives from (spread=1.0, min_dist=0.5). Store as `X_umap` (n_cells x 2), column order (component 1, component 2) as produced by the algorithm. Anchor: `sc.tl.umap(adata)`.

**Step 13 — Leiden, default setting.** Cluster the cells with the Leiden algorithm on the undirected, weighted connectivity graph, maximizing modularity at resolution 1.0, starting from singletons, with exactly 2 iterations, algorithm randomness seeded with 0. Store labels as strings ("0", "1", ...) in `leiden`, with categories in natural (numeric-aware) sort order. Anchor: `sc.tl.leiden(adata, flavor="igraph", n_iterations=2)` — the igraph `community_leiden` backend (objective_function="modularity", beta=0.01, edge weights used) with the RNG seeded from 0.

**Step 14 — Leiden at three resolutions.** Repeat the same algorithm, graph, and seed at resolutions 0.02, 0.5 and 2.0, storing under the keys `leiden_res_0.02`, `leiden_res_0.50`, `leiden_res_2.00` (format: `leiden_res_` + the resolution formatted with 2 decimals in a width-4 field). Important — check each invocation separately: these calls do NOT fix the iteration count, so the algorithm iterates until the partition is stable (run-to-convergence), unlike step 13's fixed 2 iterations. Anchor: the loop `for res in [0.02, 0.5, 2.0]: sc.tl.leiden(adata, key_added=f"leiden_res_{res:4.2f}", resolution=res, flavor="igraph")`.

**Step 15 — Broad-lineage annotation.** Map the `leiden_res_0.02` labels with exactly this dictionary: {"0": "Lymphocytes", "1": "Monocytes", "2": "B Cells", "3": "Erythroid", "4": "Erythroid"}; labels not in the dictionary map to missing values. Store as `cell_type_lvl1`.

**Step 16 — Visualizations (part of the faithful workflow; render off-screen; figures need not be saved and are not graded).** Violin plots of per-cell n_genes_by_counts, total_counts, pct_counts_mt; joint scatter of total_counts vs n_genes_by_counts colored by pct_counts_mt; the HVG means/dispersions plot; the PCA variance-ratio plot (50 PCs, log scale); PCA scatter panels (dimension pairs (0,1) and (2,3)) colored by sample and by pct_counts_mt; UMAP colored by sample; UMAP colored by `leiden`; UMAP colored by [leiden, predicted_doublet, doublet_score]; UMAP colored by [leiden, log1p_total_counts, pct_counts_mt, log1p_n_genes_by_counts]; UMAPs colored by the three `leiden_res_*` labelings with on-data legends; marker-gene dotplots of the dictionary below grouped by `leiden_res_0.02` and by `leiden_res_0.50` (expression standardized per gene); a top-5 DE genes per cluster dotplot grouped by `leiden_res_0.50`; and a UMAP colored by the five top-ranked genes of the cluster labeled "7" plus the `leiden_res_0.50` labels (skip only this last panel if your resolution-0.50 labeling has no label "7"). Marker dictionary (cell type → marker genes; source-defined prior knowledge): CD14+ Mono: FCN1, CD14; CD16+ Mono: TCF7L2, FCGR3A, LYN; cDC2: CST3, COTL1, LYZ, DMXL2, CLEC10A, FCER1A; Erythroblast: MKI67, HBA1, HBB; Proerythroblast: CDK6, SYNGR1, HBM, GYPA; NK: GNLY, NKG7, CD247, FCER1G, TYROBP, KLRG1, FCGR3A; ILC: ID2, PLCG2, GNLY, SYNE1; Naive CD20+ B: MS4A1, IL4R, IGHD, FCRL1, IGHM; B cells: MS4A1, ITGB1, COL4A4, PRDM1, IRF4, PAX5, BCL11A, BLK, IGHD, IGHM; Plasma cells: MZB1, HSP90B1, FNDC3B, PRDM1, IGKC, JCHAIN; Plasmablast: XBP1, PRDM1, PAX5; CD4+ T: CD4, IL7R, TRBC2; CD8+ T: CD8A, CD8B, GZMK, GZMA, CCL5, GZMB, GZMH, GZMA; T naive: LEF1, CCR7, TCF7; pDC: GZMB, IL3RA, COBLL1, TCF4. If your stack cannot render a visualization, proceed — the graded contract is the three output files — but do not remove or alter any computational step of this procedure.

**Step 17 — DE ranking.** For each cluster of the `leiden_res_0.50` labeling (all clusters, taken in the labeling's natural category order), rank all retained genes by a two-sided Wilcoxon rank-sum (Mann–Whitney) test of that cluster's cells versus all other cells, computed on the log-normalized expression matrix (not raw counts, not the step-7 copy, no gene mask, no raw slot):
- `scores` = the standardized statistic z = (R − n(N+1)/2) / sqrt(n(N−n)(N+1)/12), where R is the sum over the cluster's cells of the average ranks of the gene (ranks computed across all cells; average ranks for ties), n is the cluster size, N the total cell count; no tie correction;
- `pvals` = two-sided normal-approximation tail probability 2·(1 − Phi(|z|));
- `pvals_adj` = Benjamini–Hochberg adjustment of the `pvals` over all genes within the same cluster;
- `logfoldchanges` = log2((expm1(m_in) + 1e-9) / (expm1(m_rest) + 1e-9)), where m_in and m_rest are the means of the log-normalized values in the cluster and in all other cells, and expm1 inverts the natural log1p;
- within each cluster, genes are ordered by descending score (this order is the stored ranking; exact ties may occur — e.g., genes with identical values in every cell score 0 — and their relative order is arbitrary).
Anchor: `sc.tl.rank_genes_groups(adata, groupby="leiden_res_0.50", method="wilcoxon")` with defaults (reference="rest", corr_method="benjamini-hochberg", tie_correct=False, all genes, use_raw=False because no raw slot exists, layer=None).

## 4. Outputs

Write three files into the task output directory (task-relative `outputs/`).

**(a) `outputs/cell_clusters_umap.csv`** — CSV with header, UTF-8, one row per remaining cell, in the analysis row order (s1d1 cells in file order, then s1d3 cells in file order). First column `cell_id` (the unique cell names from step 2), then exactly these columns in order: `sample`, `leiden`, `leiden_res_0.02`, `leiden_res_0.50`, `leiden_res_2.00`, `cell_type_lvl1`, `umap_1`, `umap_2`. `sample` is `s1d1` or `s1d3`; the four cluster/annotation columns hold the labels as plain strings; `umap_1`/`umap_2` are the two embedding components as decimal numbers at full precision.

**(b) `outputs/rank_genes_groups_leiden_res_0.50.csv`** — CSV with header, UTF-8, columns in exactly this order: `group`, `names`, `scores`, `pvals_adj`, `pvals`, `logfoldchanges`. Exactly one row per (cluster of the `leiden_res_0.50` labeling, gene) pair — every gene retained after step 5, once per cluster. `group` holds the cluster labels exactly as they appear in the `leiden_res_0.50` column of output (a); `names` holds the gene names as produced by steps 1–2; the remaining columns hold the corresponding values. Rows are grouped by cluster with blocks in ascending natural-sorted group-label order, and within each block in the stored ranking order (scores non-increasing). Grading identifies rows by (group, gene) and by the within-group rank order; the block ordering itself is a representation detail.

**(c) `outputs/rank_genes_groups_params.json`** — a JSON object with exactly these keys and values: {"groupby": "leiden_res_0.50", "reference": "rest", "method": "wilcoxon", "use_raw": false, "layer": null, "corr_method": "benjamini-hochberg"}.

## 5. Identity, alignment and equivalence rules

- **Cell identity**: `cell_id` values are exactly the unique names produced in step 2; s1d1 barcodes never carry a deduplication suffix, and a s1d3 barcode that also occurs in s1d1 carries "-1". `cell_id` and `sample` together make every row's sample origin unambiguous.
- **Gene identity**: gene names are the feature names made unique in step 1, inner-joined across the two samples in step 2, and filtered in step 5; they are not renamed further.
- **Cluster labels**: string community indices. Each of the four clustering columns labels its own partition and is not comparable across solutions by value. Labels must be internally consistent: the labels in output (b)'s `group` column must be exactly the labels of output (a)'s `leiden_res_0.50` column, and `cell_type_lvl1` must be the step-15 dictionary applied to output (a)'s `leiden_res_0.02` labels.
- **Ties**: rows with identical scores within one cluster are interchangeable in order.
- **Determinism**: all stochastic steps are seeded with 0 as specified; no additional stochastic steps, subsampling or downscaling may be introduced.
