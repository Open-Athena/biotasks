🤖 #67 exposed a scheduling failure distinct from verifier timeouts: NiBabel PR1291 finished a positive, clean control pair and its evidence readback, but the controller stopped before cleanup submission because the exact owner worker no longer had the declared resources. [Recorded compatibility check](https://github.com/Open-Athena/biotasks/blob/1d5ac370/experiments/67-broader-pr-yield/worker-compatibility-20261026.json): 191 CPUs available, approximately 0.473 GiB declared memory headroom, versus the frozen cleanup request of 2 CPUs / 4 GiB RAM / 4 GiB disk. Nothing was submitted, and the tests were not repeated. The result remains outside completed-control counts until cleanup is verified.

The negative reported disk headroom is a conservative connector calculation, not a live measurement proving the host disk is full. Static inspection of the pinned local Iris SDK shows disk metadata comes from free filesystem bytes probed at worker startup, while our connector subtracts running jobs' declared disk requests from it; Iris's scheduler capacity accounting itself tracks CPU, memory and devices. No live filesystem probe was performed. Memory headroom independently fails the unchanged cleanup requirement, so reinterpreting the disk number alone would not unblock this attempt.

The broader lifecycle gap is that our CPU-hour cleanup reservation is an accounting allowance, not a physical placement reservation. Another workload can take the released resources between test completion and cleanup admission. A scalable follow-up should compare keeping the original allocation alive through verified archival and cleanup against reserving an owner-local cleanup slot. It must preserve owner-scoped deletion, archive-before-deletion evidence, accurate resource checks, and the rule that cleanup recovery never reruns primary tests. No resource override, scheduler change, new capacity or new execution is admitted by this diagnosis. The exact-worker waiter and guarded one-shot cohort handoff are documented in #67; this remains an agent-owned follow-up under #33.
