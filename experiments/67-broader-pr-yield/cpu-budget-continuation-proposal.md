# Prepared continuation proposal — not applied

The current campaign ledger caps cumulative additional allocated CPU time at 32 hours. Each unchanged native job requires a worst-case primary allowance of 6 CPU-hours plus cleanup and stop reserves (about 6.333 CPU-hours total). Admission therefore stops once settled usage approaches 25.667 CPU-hours, even though that is below 32 hours actually allocated. This is the campaign's conservative reservation policy, not a native test failure or an OpenRouter spending limit.

If that guard stops the current run, the proposed amendment changes only the cumulative campaign CPU allowance from 32 to **64 CPU-hours total**, using the same existing reserved TRC workers. The cumulative $90 operating ceiling (strictly below the user's $100 extra spending limit), existing storage reserve, original per-repository model settings/stop threshold/turn limit, job resources, native timeouts, source identities and test/grading contracts remain unchanged. This does not purchase workers or grant a new monetary allowance.

The resumed controller would finish the remaining independent controls for the existing NiBabel/DendroPy exports, then attempt the already-frozen AnnData and Biopython first-generation runs and their controls under the same admission checks. It would reuse existing receipts and completed generation. It would not regenerate NiBabel or DendroPy, revisit their unentered history backlogs, add repositories, retry failed native tests, or add repair-model calls. All work would still stop at the amended cumulative limits; completion is not guaranteed if individual controls consume their worst-case allowances.

The 64-hour proposal leaves room for the two remaining generation jobs (at most 12 primary CPU-hours together), typical observed control costs, and a final job's worst-case reservation. It is a proposed planning ceiling, not a measured forecast. No limit is changed or additional execution admitted by this document. The existing 32-hour ceiling stays in force until a budget amendment is authorized and recorded in the ledger and epic summary.
