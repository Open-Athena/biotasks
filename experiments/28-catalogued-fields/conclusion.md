### Implications for an automated pipeline

The observed yield is insufficient to claim reliable unattended generation under these settings. Several failures are upstream engineering boundaries: acquisition/API error handling, oversized command-argument transport, binary patch handling, parser coverage, test scope and timeout cancellation. Bootstrap model/shell formatting and historical dependency compatibility are additional boundaries. More CPUs alone would not fix them; this experiment does not isolate CPU sensitivity or predict repaired yield.

Matchms's post-fix argument was 425,528 bytes; OHIF's was 146,149 bytes, with split-patch hashes matching the original events. These are read-only reconstructions, not executed fixes. MNE's unchanged saved command retains broad `mne/` scope; both pytest parsers return empty maps despite colored progress. A read-only snapshot observed previously timed-out pytest main processes still runnable as later stages proceeded; Docker client timeout does not explicitly cancel them. No ANSI normalization, regrading, manual kill, quantified slowdown or OOM attribution is claimed. OHIF's first pair has four post-only cases and source-side Jest configuration changes; collection dependence is plausible but was not isolated.

A useful next experiment would test deterministic acquisition/transport/cancellation/parser hardening separately from historical environment construction and model choice, preserving this unchanged baseline. No such implementation or extra run is included here.
