This extends the completed September baseline at the user's request. ## Inputs and minimal adaptations

No model/package/interpreter/parser/transport/test repairs or extra model calls are permitted.

The user agreed to the history-wide discovery direction and minimal justified pagination/batch adaptations before this implementation. Concrete source and fixtures are checkpointed before any native/model execution:

- `discovery_adapter.py` replaces only the `gh pr list` transport. It supplies contiguous batches of at most 100 frozen PR identities from the complete inventory, in deterministic createdAt-descending order. Each descriptor is read using `gh pr view` with the original descriptor fields; the original native `list_merged_prs` function, draft/date checks, base-SHA REST lookup and summary construction execute unchanged. This bypasses the upstream 1000-row fetch ceiling without handpicking candidates. Descriptors are fetched at execution time and retained separately; only PR identities were frozen during inventory.
- `run_history.py` invokes the official CLI serially over those batches, with no date filter and native limit100. The first invocation uses a fresh repository bootstrap cache; later invocations use upstream's own saved-cache behavior. Entered PRs and native discovery omissions are recorded once, never retried. After a native abort, only untouched remaining identities may enter a subsequent batch. Native errors remain failures, not repaired outcomes. An acquisition/bootstrap failure with no returned list stops that repository. The explicit backlog includes all identities not entered or omitted by original discovery.
- Every new native invocation creates/cleans its validation sandbox through upstream's ordinary lifecycle. Thus batch boundaries can clear earlier sandbox processes; this is a disclosed batching consequence, not an assertion that runtime timing matches the original single-invocation baseline. No timeout process is manually killed or validation command rewritten.
- The existing resource/image/network/observer/cleanup wrappers are reused byte-for-byte, except the generation orchestrator and one supervisor environment argument that communicates the already existing native-stage deadline. The model observer additionally enforces the campaign reservation and cumulative twenty-call/per-repository actual-$5 stop across batches. It forwards identical arguments and returns the original response. No extra generation, fallback or retry request is added.
