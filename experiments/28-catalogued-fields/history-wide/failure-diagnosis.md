## Which limits belong to which layer

| Boundary | Original value | Ownership / implication |
| --- | --- | --- |
| Git checkout | 60 seconds | Hard-coded upstream acquisition timeout in `bootstrap/runner.py`; distinct from the model/bootstrap deadline. |
| Bootstrap | 1,800 seconds / 20 turns | Experiment configuration passed to upstream. More seconds do not increase the turn allowance or guarantee a saved environment. |
| Bootstrap shell execution | Default 300 seconds | Upstream Docker execution default; changing only the outer deadline does not necessarily extend an individual command. |
| Native pre/post validation | 600 seconds per stage | Upstream `validation_timeout_sec` option. It applies to each stage, despite an imprecise source comment calling it a per-PR cap. |
| Independent exported-task verifier | 300 seconds | Original generated task limit used by Harbor, with its original built-in timeout retry. A longer verifier comparison must record an explicit override/derived configuration and preserve original task bytes. |
| Native / control CPU quota | 1.5 / 1 CPU | Our infrastructure resource caps, not an intrinsic Repo2RLEnv requirement. No controlled measurement yet attributes a failure to CPU scarcity. |
| Native generation / control allocation | 84 minutes / 1 hour | Our orchestration allocation. The 21-minute new-batch reserve and control cutoff leave backlog/unstarted work; these are not failed tests. |

## Priorities for a scalable automated pipeline

1. **Complete already-generated controls.** Fourteen individual Matchms/OHIF controls never started. Give the queue sufficient total time while retaining original per-command limits. This measures scheduling loss without regenerating tasks or spending on bootstrap. Separately, use Scanpy's existing export for a longer-verifier comparison.
2. **Test the two direct acquisition/bootstrap limits.** OpenMS checkout and MMseqs2 bootstrap are small, explicit comparisons. Keep model, inputs and other limits fixed, and report any next blocker rather than continuing into an informal repair loop.
3. **Fix shared deterministic execution defects.** The command-size failure affects 33 attempted PRs across MACS, Matchms, Cobrapy and OHIF. Passing scripts/patches through stdin or files instead of one argument is a generic upstream transport change. Verify byte preservation and exit/timeout behavior before rerunning selected cases. The existing synthetic probe demonstrates the mechanism, not that all 33 tasks will become valid.
4. **Handle lifecycle and runner coverage explicitly.** Rebuild compiled code after each historical reset; make runner selection and parsing reliable; reject or mark incomplete timed-out runs rather than treating partial parsed logs as complete evidence. These need justified code changes, not just larger timeouts. SAMtools may require a supported-runner extension rather than a configuration adjustment.
5. **Make work resumable and failures observable.** Persist PR states, complete control queues independently, record failed metadata responses safely, and use bounded retries only for specified transient errors. Large-diff HTTP406 needs a different acquisition path rather than blind retry. Record time, resource use, command status and remaining work so a fixed wall clock is not mistaken for low task yield.

The first round should be small and diagnostic, not a blanket rerun of all ten repositories with larger limits. Predeclare cases by failure class, preserve baseline evidence, change one factor at a time where possible, and count recovery only after complete positive controls. Where two fixes are prerequisites, report that combined comparison explicitly rather than assigning causality to either one.

No recovery rate, additional spend, new resource allocation or successful fix is claimed here. Original model/CPU spending remains unchanged. Any run proposal must include concrete settings and fit an agreed remaining allocation; the original campaign's spent budget is not reset. The user's requirement remains an automated pipeline with only upstream's built-in LLM calls, without added LLM/Codex repairs of individual environments, tests or tasks.
