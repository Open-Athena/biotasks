# Explicit pytest targeting policy

The eight-case pinned-selector audit (`pytest-targeting-audit.json`) executes only the upstream selection function, never the generated shell. Besides preserving `mne/`, it mistakes a `--junitxml` path value for test scope, misses the `.` root target, and can append changed paths to a later `echo` or `tee` instead of pytest. These are observed string transformations, not biological runtime failures. The earlier broad-path/pathless fixtures remain valid but do not cover these command forms.

A general MNE comparison must therefore avoid unrestricted string replacement. Keep the original command as the baseline. A separately declared `changed-files` policy may replace a broad directory target only when every surviving changed Python test file lies below that directory. Preserve flags, option values and any test-name/marker filters. Preserve explicit node IDs and file targets by default; do not silently broaden or replace them. Refuse ambiguous syntax rather than guessing. Unknown option arity, expansions, pipelines, redirects, command substitutions and multiple test invocations need explicit unsupported outcomes until supported by a shell-aware implementation. A recognized `cd /workspace &&` prefix can be handled separately from a single literal pytest invocation.

The first implementation should accept a deliberately small, documented argv grammar and retain original command bytes when not changing selection. Its fixture matrix must cover quoting, option values, `--`, directory containment, dot targets, explicit files/node IDs, deleted/renamed files, unknown flags and shell suffixes. Run the same selection function for native validation and exported verification. Unsupported command syntax is not evidence that the repository is unsuitable.

Narrowing a full-suite command changes regression coverage even when it aligns with upstream's changed-file strategy. Report baseline and candidate selected test IDs, complete execution status and F2P/P2P sets separately; do not claim preservation of the full-suite contract. Hold transport, parser/completion policy, environment and time allowance fixed within that comparison. A later timeout change is another arm. No original partial MNE logs may be promoted into validated results.

Before a live MNE comparison, freeze retained PR base/head/test patches and the original command, establish a replayable environment without per-task repairs, and record an aggregate resource reservation within the remaining #32 allowance. Neither this audit nor the policy is an implemented targeting adapter or a recovered task. SAMtools Perl recognition and runner output remain a separate required investigation; a pytest policy cannot answer that question.

## Standalone policy candidate

`pytest_target_policy.py` now implements the literal-command policy as a standalone experiment. Twenty-six checks cover default-off byte preservation, the recorded MNE command shape, flags and quoted values, `--`, directory containment, explicit selections, unsafe paths, shell syntax and unknown option arity. Every selected arm is marked as reducing scope, including pathless whole-suite commands. Unsupported decisions retain the original bytes for evidence but must not be executed as a changed-files comparison. Explicit file/node selections remain unchanged.

This helper has not been wired into the upstream pipeline. Next, integrate one shared function into native/export selection with an explicit default-off option and structured unsupported outcomes, apply deletion filtering before selection, verify full-package configuration/task construction, and bind frozen MNE inputs before remote execution. Standalone checks do not establish integration, task validity or historical environment compatibility.
